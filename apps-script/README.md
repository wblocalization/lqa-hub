# ИИ-backend для LQA Hub (Google Apps Script)

Этот скрипт соединяет платформу с ИИ-моделью. Он хранит ключ API у себя: ключ не попадает ни в браузер, ни в файл платформы. Один и тот же адрес проверяет:

- **строки перевода**: раздел «Проблемы», отметить строки → «ИИ-проверка выбранных»;
- **скриншоты**: раздел «Визуальная проверка», сессия → «ИИ-проверка»;
- **общий вывод по сессии**: там же, кнопка «ИИ-вывод» — короткий разбор страницы и что исправлять первым.

Поддерживаются два провайдера: **Claude** (Anthropic) и **OpenAI**. Нужен ключ API одного из них.

## Установка (10 минут)

1. Открой [script.google.com](https://script.google.com) → **Новый проект**. Назови его, например, «LQA Hub AI».
2. Удали всё в файле `Code.gs` и вставь содержимое [`ai-review-appsscript.gs`](./ai-review-appsscript.gs). Нажми 💾 **Сохранить**.
3. Слева ⚙️ **Настройки проекта** → внизу **Свойства скрипта** → **Добавить свойство**. Добавь:

   | Свойство | Значение |
   |---|---|
   | `PROVIDER` | `anthropic` (Claude) или `openai` |
   | `ANTHROPIC_API_KEY` | ключ с [platform.claude.com](https://platform.claude.com), если PROVIDER = `anthropic` |
   | `OPENAI_API_KEY` | ключ с [platform.openai.com](https://platform.openai.com), если PROVIDER = `openai` |
   | `ACCESS_TOKEN` | придумай длинную случайную строку, например `lqa-7f3k9q2m8x`. Без неё backend будет отвечать любому, кто узнает адрес, и тратить твой лимит |
   | `MODEL` | *необязательно*: своя модель. По умолчанию `claude-opus-5` для Claude и `gpt-4o-mini` для OpenAI |

4. Проверь, что всё работает: сверху выбери функцию **`testConnection`** → **Выполнить**. При первом запуске Google попросит разрешения, разреши. В **Журнале выполнения** появится ответ модели по тестовой строке.
5. Справа сверху **Начать развертывание** → **Новое развертывание** → тип ⚙️ **Веб-приложение**:
   - «Запуск от имени»: **Я**;
   - «У кого есть доступ»: **Все**. Иначе браузер не достучится. Защищает `ACCESS_TOKEN`.
   
   Нажми **Начать развертывание** и скопируй **URL веб-приложения**: он заканчивается на `/exec`.
6. В платформе: **Настройки → Проверка ИИ**:
   - Backend: **Включён**;
   - Адрес backend: вставь URL из шага 5;
   - Ключ доступа: тот же текст, что в `ACCESS_TOKEN`;
   - нажми **Сохранить**, потом **Проверить подключение**. Должно появиться «✓ Работает: Claude, модель claude-opus-5» (или OpenAI).

## Командное хранилище

Тот же скрипт хранит общие данные команды на Google Диске. Туда попадают проекты, строки, проблемы, решения, комментарии, скриншоты и правила проверки. Ключ ИИ для этого не нужен: хватит шагов 1–2 и 5 выше и `ACCESS_TOKEN`.

1. Если скрипт уже был развёрнут раньше, обнови код из [`ai-review-appsscript.gs`](./ai-review-appsscript.gs). Затем **Развертывание → Управление развертываниями → ✏️ → Версия: новая → Развернуть**. Google попросит разрешить доступ к Диску, разреши: там будут лежать данные.
2. У каждого участника команды в платформе: **Настройки → Проверка ИИ** — тот же адрес backend и тот же ключ доступа. Затем **Настройки → Командное хранилище → Включить**.
3. Первым включает тот, у кого уже есть данные. Остальные при включении получают данные команды, а их собственные записи добавятся к общим.

Как это работает:
- Изменения синхронизируются сами: раз в минуту, после любых правок и при возвращении на вкладку. Значок облака в верхней панели показывает состояние, по клику синхронизация запускается сразу.
- Данные лежат в папке **«LQA Hub — данные»** на Диске владельца скрипта: по файлу на таблицу, скриншоты отдельными файлами. Папку можно задать свойством `DATA_FOLDER_ID`.
- Если два человека одновременно поменяли **одну и ту же** запись, остаётся версия того, кто синхронизировался позже. Разные записи сливаются без потерь.
- Адрес backend, ключ доступа и настройки ИИ у каждого свои и не синхронизируются.
- Все, у кого есть адрес и ключ доступа, видят все данные. Держи `ACCESS_TOKEN` внутри команды.

## Доступ только по Google-почтам

По умолчанию backend отвечает всем, кто знает адрес и `ACCESS_TOKEN`. Чтобы пускать только одобренные Google-почты:

1. В платформе: Настройки → «Вход через Google» — вставь Client ID (как его получить, написано в карточке).
2. В Apps Script обнови код из `ai-review-appsscript.gs`.
3. «Настройки проекта» → «Свойства скрипта», добавь:

   | Свойство | Значение |
   |---|---|
   | `ADMIN_EMAILS` | твоя почта (можно несколько через запятую). Администраторы всегда имеют доступ и меняют список |
   | `GOOGLE_CLIENT_ID` | тот же Client ID, что в платформе |

4. «Развернуть» → «Управление развёртываниями» → карандаш → «Новая версия» → «Развернуть». Адрес не меняется.
5. Обнови платформу, войди через Google своей почтой. В Настройках появится карточка «Доступ по Google-почтам» — впиши почты команды по одной в строке и нажми «Сохранить список».

Что меняется:
- каждый запрос несёт свежий вход Google (ID token), backend проверяет подпись у Google, что токен выдан для твоего Client ID и что почта есть в списке;
- кто не вошёл или чьей почты нет в списке, видит экран входа и не получает данные команды;
- `ACCESS_TOKEN` в этом режиме не нужен; уберёшь `ADMIN_EMAILS` — всё вернётся к доступу по ключу.

Данные, которые человек уже загрузил к себе в браузер раньше, остаются у него в браузере — список закрывает доступ к общему хранилищу и ИИ.

## Редполитики для ИИ

В платформе: Настройки → «Редполитики» → «Добавить редполитику». Выбери язык и вставь ссылку на Google Документ, загрузи файл .docx / .txt или вставь сам текст. Файл читается прямо в браузере, backend его не открывает. ИИ-проверка строк и скриншотов этого языка получит её вместе с глоссарием и будет проверять стиль, обращение и оформление.

- Документ читает backend от имени аккаунта, от которого развёрнут скрипт: дай этому аккаунту доступ на чтение.
- Нужен именно Google Документ. Загруженный .docx открой и выбери «Файл → Сохранить как Google Документ».
- После обновления кода Apps Script при развёртывании попросит новое разрешение — на чтение Google Документов. Это нормально.
- Текст кэшируется на 6 часов и обрезается до 30 000 символов. Кнопка «Проверить» в карточке показывает, сколько текста видит ИИ.

## Если что-то не так

| Что видишь | Что сделать |
|---|---|
| «Не удалось достучаться» | Проверь, что URL заканчивается на `/exec`, а в развертывании доступ «Все». |
| «Неверный ключ доступа» | Текст в поле «Ключ доступа» должен совпадать с `ACCESS_TOKEN` до символа. |
| «…ответил 401: неверный ключ API» | Проверь `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` и что на аккаунте провайдера есть баланс. |
| Значок облака красный | Наведи на него: там причина. Чаще всего это старая версия скрипта без хранилища (обнови развертывание, шаг 1 выше) или нет разрешения на Диск. |
| «…ответил 429» | Слишком много запросов подряд или закончился лимит. Подожди минуту. |
| «Ответ модели оборвался» или долгие проверки строк | Уменьши «Строк за один вызов» в Настройках, например до 10. |
| Код скрипта изменился (например, обновился из репозитория), а работает по-старому | После правок нужно **Развертывание → Управление развертываниями → ✏️ → Версия: новая → Развернуть**. URL при этом не меняется. |

## Сколько это стоит

Платишь провайдеру за каждый запрос. Проверка одного скриншота 1280×720 — это примерно 1–2 тысячи токенов на входе плюс ответ. Пачка из 15 строк — в том же порядке. Актуальные цены: [Claude](https://platform.claude.com/docs/en/about-claude/pricing), [OpenAI](https://openai.com/api/pricing). Чтобы тратить меньше, запускай ИИ по строкам, которые уже отметила техническая проверка, и по скриншотам, где что-то подозрительно.

## Как это устроено (для разработчика)

Платформа шлёт `POST` на URL веб-приложения, тело — JSON (`Content-Type: text/plain`, чтобы Apps Script не требовал CORS preflight). Поле `token` сверяется с `ACCESS_TOKEN`.

- `{"mode":"ping"}` → `{"ok":true,"provider":"anthropic","model":"claude-opus-5"}`
- `{"mode":"visual","image":"data:image/webp;base64,…","language":"kk","languageName":"Казахский","page":"Главная","pageUrl":"…","glossary":[{"term","approved"}]}`
  → `{"findings":[{"type","severity","text","found","expected","box":{"x","y","w","h"}}]}`. Рамка задаётся в долях от размера картинки (0..1).
- `{"mode":"summary","findings":[{"type","severity","text","found","expected","status","screen"}],"language","languageName","page","shots"}`
  → `{"summary":"…","priorities":["…"],"verdict":"Можно выпускать | Выпускать после исправления критичных | Не готово"}`
- `{"items":[{"id","source","target","language","component","context","glossary"}]}`
  → `{"results":[{"id","has_issue","type","severity","explanation","suggestion","confidence"}]}`
- При ошибке: `{"error":"текст ошибки"}`.

Ответ модели ограничен JSON-схемой (structured outputs у обоих провайдеров), поэтому типы и важность всегда из списков платформы. Для Claude Opus 5 включены серверные fallbacks (`fallbacks: "default"`): если фильтр безопасности отклонит запрос, API сам повторит его на подходящей модели.
